## TBKK

**Pet-проект**
**Жанр:** 3D Puzzle-Adventure с элементами симуляции
**Команда:** один я
**Год:** 2026
**Стек:** Unity, C#, Git, NavMesh, QuickOutline
**Платформа:** Windows
**GitHub:** [github.com/bhgou/TBKK](https://github.com/bhgou/TBKK)

### Об игре

TBKK — 3D-игра от третьего лица в жанре puzzle-adventure в городской/индустриальной среде. Игрок управляет персонажем click-to-move, исследует локацию с машинами, светофорами, конвейерами и NPC. Геймплей строится на Drag-and-Drop предметов из инвентаря на объекты мира: собрать карточку-ключ, открыть турникет, пройти мини-игру со считывателем, уворачиваться от машин.

### Что реализовано за 29 коммитов

- Click-to-move контроллер с Lerp и анимацией ходьбы
- AI машин: Raycast-детекция препятствий, светофоров и игрока
- Система светофоров: циклическое переключение цветов, синхронизация с трафиком
- Инвентарь: Singleton, UI-сетка, ScriptableObject предметы, Drag-and-Drop
- Головоломка с турникетом: карточка-ключ → swipe-мини-игра → анимация двери
- Диалоговая система: ScriptableObject с именем/аватаром/текстом
- NPC патруль по NavMesh
- Конвейерная лента с зацикливанием
- Outline-подсветка интерактивных объектов

### Технические решения

#### Drag-and-Drop система

- **Проблема:** Нужен простой способ использовать предметы на объектах мира без меню.
- **Решение:** Перетаскивание из UI Cell с Raycast при отпускании → вызов Use() у UseItemInventoryObject.
- **Эффект:** Интуитивный интерфейс без лишних кликов.

#### Car AI + Traffic Light

- **Проблема:** Машины должны ездить, реагировать на светофоры и не врезаться.
- **Решение:** Raycast вперёд — при Stop-триггере (зелёный) остановка, при End-триггере зацикливание. Детекция игрока → смерть.
- **Эффект:** Адекватное движение машин по маршруту.

## Horror Project (WIP)

**Pet-проект** *(ранняя стадия)*
**Жанр:** 3D Horror от третьего лица
**Команда:** один я
**Год:** 2026
**Стек:** Unity, C#, HDRP, Git, Input System, Cinemachine, ServiceLocator
**Платформа:** Windows
**GitHub:** [github.com/bhgou/horror](https://github.com/bhgou/horror)

### Об игре

Хоррор-игра от третьего лица на HDRP. Игрок исследует мрачные локации (внутри помещений и на открытом воздухе), взаимодействует с предметами, решает головоломки, использует оружие. Проект на ранней стадии.

### Что реализовано за 2 коммита

- **Архитектура:** ServiceLocator вместо God-класса G.cs, Event-driven системы
- **Контроллер:** ThirdPersonController + CameraMouseLook + PlayerAnimator
- **Input System:** гибкая привязка клавиш через InputSettings/InputPreset
- **Оружие:** система Weapon с анимациями
- **Инвентарь:** Inventory + InventorySlot + InventoryUI
- **Взаимодействие:** SitController (сидение/вставание), IInteractable, UseSystem
- **Локации:** LocationManager + LocationData + переходы
- **Камера:** Cinemachine с LocationCameraHandler
- **Звук:** SoundManager, LocationSoundHandler
- **UI:** Dark Horror UI, индикаторы, подсказки
- **Визуал:** PSX-эффекты, VHSPro ленточный эффект, Outline

### Технические решения

#### Переход от God-класса к ServiceLocator

- **Проблема:** God-класс `G.cs` делал код связанным и сложным для расширения.
- **Решение:** ServiceLocator — регистрация через `Register<T>()`, получение через `Get<T>()`. Системы общаются через EventManager.
- **Эффект:** Модульный код, легко заменять системы без изменения десятков файлов.

## Cube Collector

**Pet-проект**
**Жанр:** Hyper-Casual 3D collectator для Yandex Games
**Команда:** один я
**Год:** 2026
**Стек:** Unity, C#, URP, Git, DOTween, Yandex SDK (PluginYourGames), ServiceLocator, EventManager, PlayerPrefs
**Платформа:** WebGL (Yandex Games)
**GitHub:** [github.com/bhgou/cube-collector](https://github.com/bhgou/cube-collector)

### Об игре

Hyper-casual 3D-игра, где игрок собирает кубики, проходит уровни и зарабатывает монеты. Ориентирована на Yandex Games: экономика, магазин бустеров, ежедневный бонус, комбо-система, реклама (Rewarded + Interstitial), полный WebGL-цикл.

### Что реализовано за 7 коммитов

- **Экономика:** MoneyManager (PlayerPrefs), выдача монет за уровень
- **Магазин:** ShopController + ShopManager, UI из GUI Pro-CasualGame
- **Бустеры:** ExtraMoves (+3 хода), Magnet, PowerUpManager
- **Реклама:** YandexAdsProxy (заглушка/продакшн), Rewarded, Interstitial
- **Ежедневный бонус:** DailyBonusManager (7 дней)
- **Комбо-система:** множитель монет за уровни подряд
- **DOTween UI:** все анимации в hyper-casual стиле
- **Архитектура:** ServiceLocator + EventManager (из Horror Project)

### Технические решения

#### HyperCasual UI на DOTween

- **Проблема:** UI был статичным, не хватало отзывчивости.
- **Решение:** Все анимации на DOTween — Scale с OutBack, PunchScale, каскадное появление, анимированный счёт.
- **Эффект:** Быстрый упругий интерфейс в hyper-casual стиле.

#### Экономика и Yandex Games

- **Проблема:** Нужна монетизация через Yandex Games.
- **Решение:** YandexAdsProxy (заглушка + SDK), привязка рекламы к точкам: удвоение, доп. ходы, Interstitial.
- **Эффект:** Полный цикл монетизации.

## Skin Factory — Backend TG

**Pet-проект**
**Жанр:** Telegram-бот / Web App для открытия CS:GO кейсов
**Команда:** один я
**Год:** 2026
**Стек:** Node.js, TypeScript, Express, PostgreSQL, Prisma, Telegraf, JWT, React/Vite
**Платформа:** Telegram (Web App)
**GitHub:** [github.com/bhgou/backend_tg](https://github.com/bhgou/backend_tg)

### О проекте

Skin Factory — полноценная платформа в Telegram для открытия CS:GO кейсов. Бот + Web App с двумя валютами (CR/GC), системой фрагментов скинов, выводом реальных скинов на Steam, мини-играми, маркетплейсом. Полная экономика с монетизацией.

### Что реализовано за 120 коммитов

- **Бот:** Telegraf, авторизация через Telegram, меню, инлайн-кнопки
- **API:** Express, JWT, rate limiting, валидация
- **База данных:** PostgreSQL + Prisma, миграции
- **Пользователи:** регистрация, профиль, статистика, рефералы
- **Кейсы:** открытие, выпадение фрагментов, история
- **Инвентарь:** предметы, сборка скина из фрагментов, продажа
- **Маркетплейс:** лоты, покупка/продажа, комиссия 5%
- **Мини-игры:** кости, рулетка, слоты, орёл и решка
- **Платежи:** пакеты GC, Stripe/Telegram Stars
- **Админ-панель:** управление пользователями, кейсами, скинами
- **Фронтенд:** React/Vite Web App для Telegram
- **Деплой:** Docker + Render

### Технические решения

#### Экономическая модель

- **Проблема:** Нужно обеспечить устойчивую экономику с двумя валютами без инфляции.
- **Решение:** CR (фармится в игре) тратится на кейсы и базовые действия. GC (покупается за деньги) — на премиум-кейсы, ускорение, маркет. Комиссия рынка 5%, преимущество казино в мини-играх.
- **Эффект:** Сбалансированная экономика с прогнозом дохода 200k-2M ₽/мес.

#### Система вывода скинов

- **Проблема:** Напрямую выдавать скины — дорого. Нужна система, мотивирующая играть.
- **Решение:** Каждый скин разбит на фрагменты (5-30 шт.). Фрагменты падают из кейсов случайно. Собрав все → обмен на реальный скин через Steam Trade Link.
- **Эффект:** Игроки возвращаются, чтобы собрать полный скин.

## HelpOnRoad

**Pet-проект**
**Жанр:** Платформа для взаимопомощи на дорогах (Mobile + Web)
**Команда:** один я
**Год:** 2026
**Стек:** TypeScript, React Native, Expo, Node.js, Express, MariaDB, Docker, Nginx
**Платформа:** iOS, Android, Web
**GitHub:** [github.com/bhgou/helponroad](https://github.com/bhgou/helponroad)

### О проекте

HelpOnRoad — платформа, где пользователи могут создавать метки на карте с запросами о помощи на дороге (спустило колесо, закончился бензин, нужен буксир) и указывать вознаграждение. Компании регистрируются, видят запросы рядом и оказывают услуги. Полный DevOps: Docker, Nginx, SSL, Ubuntu.

### Что реализовано за 18 коммитов

- **Мобильное приложение:** Expo/React Native, карта Leaflet, экраны регистрации/профиля/меток
- **Сервер:** Node.js/Express, MariaDB, SQL миграции
- **API:** аутентификация, CRUD меток, компании, профиль, аватар
- **Карта:** создание меток с геолокацией, просмотр активных меток рядом
- **Компании:** регистрация, профиль, управление сотрудниками
- **DevOps:** Docker Compose, Nginx reverse proxy, Let's Encrypt SSL, deploy-скрипты
- **Безопасность:** bcrypt, параметризованные SQL, CORS, валидация

### Технические решения

#### Полный цикл деплоя на Ubuntu

- **Проблема:** Нужно развернуть production-сервер с БД, SSL и reverse proxy.
- **Решение:** Docker Compose (сервер + MariaDB), Nginx как reverse proxy, Certbot для SSL, bash-скрипты для одной команды деплоя.
- **Эффект:** `./deploy.sh deploy` — и приложение работает на сервере с HTTPS.

#### Карта и метки в реальном времени

- **Проблема:** Пользователи должны видеть актуальные запросы помощи на карте.
- **Решение:** Leaflet для отображения, REST API с пагинацией и фильтрацией по радиусу. Метки с геолокацией, статусом и вознаграждением.
- **Эффект:** Быстрая загрузка меток, удобный просмотр запросов рядом.
